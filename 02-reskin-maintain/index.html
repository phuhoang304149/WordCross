Agent đọc trước

Template chung vs Bản riêng

  • TEMPLATE CHUNG (body data-mode="template"): không chứa tiến độ, ID, tên project thật. Không sửa bằng tiến độ project.
  • BẢN RIÊNG: copy NGUYÊN folder vào root project, đổi data-mode="private", rồi điền.
  • Cập nhật bản riêng NGAY sau mỗi quyết định/kết quả, ở checkout chính, kể cả khi code nằm trong worktree.

Cách agent sửa HTML nguồn

  • Input: sửa value="…". Select: đặt selected đúng option. Checkbox: thêm checked. Textarea: nội dung giữa thẻ.
  • Phase: sửa data-status của <section class="phase"> VÀ option selected của select data-role="status", ghi note ở textarea data-role="note".
  • Task: sửa JSON trong <script id="tasks-source"> (schema ở khu Task).

JSON snapshot (người dùng thủ công)

  • Thanh dưới cùng: Lưu JSON tải file có version, gồm mọi field (cả field đang ẩn), trạng thái phase, task, note.
  • Trang KHÔNG tự đọc file bên cạnh, KHÔNG backend. Bản riêng TỰ LƯU vào localStorage của trình duyệt đang mở (xem khu "Tự lưu") — agent không đọc được localStorage, nên vẫn cần JSON.
  • Lần đọc sau: nếu user đưa JSON mới nhất → nạp, đối chiếu rồi sửa HTML nguồn cho khớp; xuất dữ liệu xong thì cập nhật HTML + yêu cầu JSON mới nhất nhất quán.
  • JSON lỗi bị từ chối trước khi đổi bất cứ thứ gì. Không đưa secret/password vào đây.

Tự lưu trong trình duyệt

Mục tiêu, field, phase, checkbox, note và task tự lưu vào localStorage của CHÍNH trình duyệt này, tách riêng theo đường dẫn file này (template chung không tự lưu). Trình duyệt/máy/profile khác, ẩn danh hoặc xoá dữ liệu duyệt web sẽ KHÔNG có bản này, và agent không đọc được. Muốn sao lưu/bàn giao: bấm 💾 Lưu JSON.

Agent cập nhật HTML (field hoặc tasks-source) thì lúc mở lại trang sẽ merge theo ID task và từng trường: trường bạn chưa sửa lấy bản file mới, trường bạn đã sửa giữ bản của bạn, task mới trong file được thêm. Cả hai cùng sửa một trường → hiện xung đột dưới đây, chữ của bạn giữ nguyên tới khi bạn chọn.

        Ý nghĩa từng số (các nhóm CÓ THỂ giao nhau)
        • Chỉ đếm task khác Không áp dụng. Evidence = ô Evidence không rỗng.
        • Đã xác minh = Xong + loại cli-smoke/runtime/manual + có evidence. Chỉ compile/merge/code/ui KHÔNG bao giờ tính ở đây.
        • Chưa xác minh = mọi task còn lại (tổng − đã xác minh): gồm task code/compile/ui/content/ads-iap-ota đã Xong, task Xong thiếu evidence, và mọi task chưa Xong.
        • Đạt = Xong + có evidence, mọi loại: đạt tiêu chí ghi trong chính task. Task code/compile Đạt vẫn nằm trong Chưa xác minh → Đạt và Chưa xác minh giao nhau; Đạt không có nghĩa là đã chạy đúng.
        • Đang làm = trạng thái doing (có thể đã có evidence một phần, vẫn Chưa xác minh). Chưa làm = waiting + blocked + hold.
        • Tiến độ: Đạt + Đang làm + Chưa làm + Xong-thiếu-evidence = tổng. Đã xác minh ⊂ Đạt.

        Quy trình QA: QA báo kết quả kèm evidence (lệnh, commit/hash, log, thiết bị, ai kiểm, giờ) → cập nhật task NGAY: đạt thì Xong + evidence; chưa đạt thì đổi trạng thái task cũ (doing/blocked) + note, hoặc thêm task mới cho lỗi mới phát hiện (kiểm trùng trước, không nhân bản). Luồng QA KHÔNG tự sửa code/asset; việc sửa là task riêng. Không suy ra pass từ compile.

        Mỗi task: mục tiêu, phạm vi, người, phụ thuộc, tiêu chí đạt, evidence. Task kiểm đạt → trạng thái Xong + evidence NGAY; chưa đạt → note. Task độc lập chạy song song. Không áp dụng chỉ cho phần thực sự ngoài scope và PHẢI ghi lý do trong note (thiếu note = chưa chốt, vẫn block); không ép Ads/IAP/OTA khi không liên quan. Nhóm chưa có task vẫn là chưa xác minh cho tới khi có task/record Không áp dụng kèm lý do.

        Schema task (JSON trong tasks-source) 
        {"tasks":[{"id":"T001","title":"…","type":"code|compile|cli-smoke|runtime|ui|manual|content|ads-iap-ota","status":"waiting|doing|blocked|done|hold|na","screen":"màn/chức năng","goal":"","scope":"","owner":"","deps":"","criteria":"","evidence":"","note":""}]}

        Bài học thất bại → cơ chế bắt buộc

        1. Không dừng vì blocker mềm

        • Gặp thiếu: ghi blocker + lý do + đầu vào cần, hỏi ĐÚNG phần thiếu, làm tiếp việc độc lập đến hết scope.
        • Không dừng sau mỗi task hay mỗi trần CLI $2 nếu còn quyền chạy đúng cấu hình.
        • Chỉ dependency thật mới chờ. Play tạo app theo tên/package — KHÔNG có yêu cầu chọn template app trước. Ads thiếu thì tạo đúng quyền/tool, không hỏi user cấp ID vô cớ.

        2. Pass ≠ giống design

        • Compile 0 lỗi / test 10/10 không chứng minh runtime Play đúng (từng lỗi: chữ trắng nền sáng, safe area đè, wheel đè toolbar, thiếu đường nối, nút sai vị trí).
        • "300 brief" ≠ 300 nội dung thật (từng chỉ có 9 mẫu). Đếm nội dung thật.
        • Không claim full khi sample content, stub IAP, fake callback, OTA chưa xác minh.

        3. Config & artifact

        • Config phải nằm trong source, không secret, tái lập được — không chỉ override trong worktree build (từng build ra version 0 / thiếu ADS, IAP).
        • Artifact ghi chính xác version/hash/path; phân biệt candidate mới với artifact lỗi/cũ.
        • Không bỏ cache hợp lệ, không build lại vô ích. Warning token không phải license fail nếu build vẫn chạy.

        4. Lưu ngay, không hỏi lặp

        • Input user đã trả lời: ghi vào Intake ngay.
        • Rã task TRƯỚC code; task kiểm đạt tick ngay kèm evidence, chưa đạt thì note.
        • Task mới/tiếp tục: đọc Git design dirty + commits so baseline, cập nhật task bị ảnh hưởng. Không ép mọi bước tuần tự.
        • Trước khi resume: kiểm Git/CLI đang chạy để tránh chạy trùng.

        Intake bản cập nhật

        Điền từ yêu cầu user + hiện trạng. Hỏi CHỈ field thiếu/mâu thuẫn; trả lời xong lưu ngay. Không nhập password/secret.

        Đọc project/source/config TRƯỚC khi hỏi để tự điền package Android/bundle ID iOS, tên app, version hiện tại, keystore PATH + alias/cấu hình signing hiện hữu. Chọn file đúng engine thực tế (ví dụ Gradle/manifest, Info.plist/xcconfig/pbxproj, ProjectSettings Unity, pubspec, app.json… tùy project), không giả định path cố định cho mọi framework. Chỉ hỏi phần thiếu/mâu thuẫn. Giữ khóa ký + app identity, không tạo/rotate signing; không ghi password/private key/file keystore vào HTML/JSON/log/commit.
